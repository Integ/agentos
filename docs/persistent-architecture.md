# 架构概要

AgentOS 目标为 Linux 内核上的用户态 Agent OS。当前版本 **v0.3** 提供持久任务系统服务、Unix socket 协议和独立终端工作台。[v0.3 设计](v0.3-design.md)与[协议 v1](protocol-v1.md)说明接口、恢复语义和当前边界。

## 基础决策

- Linux 内核与现有驱动作为底座，Rust 实现用户态 Agent OS 层。
- 首个部署目标为 x86-64 Linux 桌面工作站；当前也支持 macOS 开发。
- 单 OS 用户，多个客户端；Unix peer credentials 提供本机账户身份。
- 任务归后台服务所有，界面与临时连接不拥有任务生命周期。
- 模型只负责规划；任务事实、授权、人工批准和执行由运行时掌握。

## 分层与实现

| 层 | 职责 | 当前实现 |
| --- | --- | --- |
| 独立交互 | 实时终端工作台、CLI、历史分页、断线恢复视图 | `agentos-cli`，可执行文件 `agentos` |
| 本地控制协议 | 版本、请求关联、受限 JSON Lines 帧、结构化错误 | `agentos-ipc` |
| 系统服务 | 本机 UID 验证、socket 生命周期、请求路由、背压、订阅 | `agentos-taskd::service` |
| Agent 执行 | 规划、计划预检、逐步授权、批准、结果记录 | `Butler`、规则及两个 HTTP 规划器 |
| 任务事实 | 持久 ID、状态、步骤、revision、分页、变更通知 | `agentos-runtime` |
| 权限与审计 | grant、风险、污点策略、同步审计、独占写入锁 | `agentos-policy`、`agentos-audit` |
| 最小应用 | 时间、持久笔记、可恢复清空 | `builtin.rs` |
| 设备抽象 | Sensor / Output trait | `agentos-core`；完整多模态路由尚未实现 |
| Linux 隔离 | 进程监督、cgroups、namespaces、seccomp、Landlock | 尚未实现；能力当前与服务同进程 |

## 任务与控制契约

客户端提交意图后，服务先预留队列容量，再持久创建 `task-N` 并入队。请求成功只表示已接收，任务执行与客户端连接互相独立；关闭工作台不取消任务。

任务状态为 `queued → planning → running → succeeded/failed`，策略可进入 `awaiting_confirmation`。取消进入 `cancelled`；服务关闭或重启将未完成任务转为 `interrupted`，清除批准请求，保留步骤现场。终态任务不会自动执行。

批准绑定任务、从 1 开始的步骤、随机令牌、系统用户来源与五分钟期限。来源由内核 peer credentials 派生，客户端不能自报身份；同一 UID 可以跨连接管理任务。每步仍重新检查 grant。取消在步骤边界生效，不假定已开始的动作回滚。

每次持久修改推进 revision，并发布有界任务变更提示。列表按 ID 倒序分页，页面与 revision 一起读取。订阅丢失或游标过旧时要求客户端重新同步；通知流不提供持久事件重放。工作台自动重连视图，不重发变更请求。

任务和应用数据通过原子快照持久化，审计同步只追加。调用前保存开始标记和运行状态，调用后保存结果；关键持久化失败停止剩余步骤。系统不承诺跨能力和日志的原子事务，也不在连接异常后推断操作未生效。

## 风险分级

| 级别 | 默认策略 | 当前边界 |
| --- | --- | --- |
| L0 `ReadOnly` | 自动执行 | 时间、笔记读取 |
| L1 `Reversible` | 自动执行，受污染上下文需确认 | 追加、可恢复清空、恢复笔记 |
| L2 `External` | 每次确认，可预授权；污染时仍确认 | 核心策略与 socket 集成测试覆盖，暂无内置外部操作 |
| L3 `Irreversible` | 确认与可信身份核验，不可预授权 | 本版无可信身份核验设备，继续拒绝执行 |

OS UID 是本机账户信任域，不是进程隔离或 L3 身份证明。`tainted` 已参与策略，但尚无端到端外部内容来源追踪。逻辑 grant 约束可信能力代码，不能隔离恶意插件。
