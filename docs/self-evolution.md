# 自我进化

用户通过输入设备（键盘、语音）提出一个 AgentOS 现在做不到的要求，AgentOS 自己写出新能力、自测、请用户审阅，确认后装上并立刻可用；不满意可以回滚。

## 设计原则

1. **长新能力，不改内核。** 进化的单位是"能力插件"（一个小脚本 + 清单），挂到能力注册表上。策略引擎、审计日志、管家 Agent 本身不会被模型改写，这样无论生成的代码多糟糕，安全边界都还在。
2. **人始终握着开关。** 生成和自测可以自动进行，但安装永远是 L3 操作：必须用户明确确认，不能预授权，正式版本还要求身份核验。
3. **沙箱默认不信任。** 插件和它的自测都在 bubblewrap 沙箱里运行：系统目录只读、看不到用户主目录、默认不能联网、只有申请了存储才有一个私有的可写目录，单次调用 10 秒超时。
4. **风险只升不降。** 插件自己声明风险等级，系统再按权限抬高：申请存储至少 L1，申请联网至少 L2；本机没有可用沙箱时，所有插件至少 L2（每次调用都要确认）。联网插件（以及没有沙箱时的所有插件）返回的内容视为不可信：任务读到它之后会被标记为“受污染”，后面任何有副作用的步骤（L1 及以上）都要人确认，防止网页里的提示注入悄悄动手。
5. **一切可追溯、可撤销。** 每个版本单独存放、永不覆盖；安装结果连同代码的 SHA-256 写入审计日志；回滚和停用都是 L1 操作。

## 流程

```
用户："学会：把摄氏度换算成华氏度"
  │
  ▼
管家 Agent 规划 → evolve.propose（L1，自动执行）
  │   ├─ 生成器（LLM）按需求写插件：清单 + 源码 + 自测用例
  │   ├─ 静态检查：名字、保留命名空间、运行时、schema、大小
  │   ├─ 沙箱自测，失败就把原因反馈给模型重写（最多 3 次）
  │   └─ 草案保存在内存里（审阅的就是安装的，磁盘上无法偷换）
  ▼
展示草案：用途、说明、权限、声明风险 → 生效风险、自测结果、完整代码（升级时为差异）
  │
  ▼
系统自动追加 evolve.install（L3）→ 请求用户确认
  │  y                                  │ 其他
  ▼                                     ▼
写入新版本并启用，管家立即获得该能力    取消，什么都不装
```

升级已安装的插件走同一条路，`evolve.propose` 的 `target` 参数指定插件名，审阅时显示与当前版本的差异。

## 能力列表

| 能力 | 风险 | 作用 |
| --- | --- | --- |
| `evolve.propose` | L1 | 生成并自测插件草案，交给用户审阅 |
| `evolve.install` | L3 | 安装审阅过的草案（由系统在草案之后自动发起） |
| `evolve.list` | L0 | 列出自生成的插件和版本 |
| `evolve.rollback` | L1 | 切回之前的版本，也用于重新启用 |
| `evolve.disable` | L1 | 停用插件，保留版本和数据 |

规则规划器（离线）里的说法：`学会：……`、`看看插件`、`回滚 <名字>`、`恢复 <名字>`、`停用 <名字>`。用 LLM 规划器时直接说需求即可，模型发现现有工具做不到时会自己调用 `evolve.propose`。

## 插件格式

```
<AGENTOS_HOME>/evolve/plugins/<名字>/versions/<n>/manifest.json
<AGENTOS_HOME>/evolve/plugins/<名字>/versions/<n>/main.py   (或 main.sh)
<AGENTOS_HOME>/evolve/plugins/<名字>/current                 当前版本号，不存在表示停用
<AGENTOS_HOME>/evolve/plugins/<名字>/data/                   私有存储，跨版本保留
```

`AGENTOS_HOME` 默认是 `~/.local/share/agentos`，可用 `--home` 或环境变量 `AGENTOS_HOME` 指定。

调用协议：参数以一个 JSON 对象写入 stdin；插件向 stdout 输出一个 JSON 对象，`message` 字段是给用户看的结果；非零退出码表示失败，stderr 是原因。插件输出中的 `follow_up` 字段会被丢弃，只有内置能力可以串联下一步。

## 资源限制

每次运行插件（包括自测）都会在子进程里设置以下 rlimit，插件派生的子进程也继承，两种沙箱模式都生效：

| 限制 | 值 | 超出时 |
|---|---|---|
| 地址空间（RLIMIT_AS） | 1 GiB | 分配失败（Python 抛 MemoryError） |
| 单个文件大小（RLIMIT_FSIZE） | 64 MiB | 写入失败 / 进程被 SIGXFSZ 结束 |
| CPU 时间（RLIMIT_CPU） | 10 秒（所有线程合计） | 进程被结束 |
| 打开的文件数（RLIMIT_NOFILE） | 256 | 打开失败 |
| core dump（RLIMIT_CORE） | 0 | 不生成 core 文件 |

另外还有 10 秒的墙钟超时和 64 KiB 的输出上限。没有用 RLIMIT_NPROC：它按真实用户统计所有进程，会误伤桌面上的其他程序；fork 炸弹靠 bubblewrap 的 PID 命名空间和超时兜底（超时后整个沙箱被杀掉）。没有沙箱时只剩超时，这也是没有沙箱时每次调用都要确认的原因之一。

## 安全上的已知限制

- 自测在用户审阅之前运行。有沙箱时这是安全的；没有沙箱时默认跳过自测并在草案里注明，避免未经审阅的代码以守护进程的权限运行。
- 申请了联网的插件，自测时也能联网（仍在沙箱内，看不到本机文件）。
- 草案只存在内存里，守护进程重启后失效，需要重新生成。
- 生成器看到的是用户的原话；如果以后让管家根据网页、邮件等外部内容发起进化，计划会被标记为受污染，所有有副作用的步骤都需要确认。
- 目前只支持 python3 和 sh 两种运行时，以及"一个插件一个能力"。

## 安装镜像需要的包

`bubblewrap` 和 `python3`。没有 bubblewrap 时插件仍可使用，但每次调用都要确认。

## 后续

- 用 cgroup（systemd scope 的 MemoryMax / TasksMax）限制整个插件进程树的总内存和进程数。
- 用 seccomp / Landlock 进一步收紧，按清单声明的域名限制联网。
- 支持 MCP server 作为插件形态，以及多能力插件。
- 进化出"技能"（组合已有能力的工作流），比写代码更轻、更安全。
- 在核心组件上做受控的自我修改：生成补丁 → 在隔离环境编译测试 → 用户确认 → A/B 分区切换，失败自动回退。
