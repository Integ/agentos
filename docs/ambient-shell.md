# 情景式图形 Shell

AgentOS 的图形入口以**意图、对话和执行结果**组织界面。语音是主要入口，键盘和鼠标提供同等可达的操作。当前实现是运行在浏览器中的本地用户态 Shell 原型，不是桌面合成器或可启动的操作系统发行版。

## 交互与视觉

界面保留稳定的导航、连接状态和底部意图入口，主要画布随当前情景改变内容及优先级。启用“AI 情景布局”后，模型根据当前任务与上下文组织主要画布；模型状态、生成中与回退状态会显示在界面中：

| 空间 | 目的 |
| --- | --- |
| 此刻 | 进入意图、发现下一步操作 |
| 专注 | 本地专注计时，减少信息干扰 |
| 记忆 | 记录和回顾笔记 |
| 轨迹 | 查看真实任务状态、步骤与结果 |

设计借鉴《Her》的安静和陪伴感、《降临》的环形语言，以及《银翼杀手》的环境氛围；使用原创的界面形状、排版和动效，不包含电影素材。电影感服务于状态表达，不用装饰性仪表假装系统正在执行任务。

说“记一下 买牛奶”进入记录，“看看笔记”进入记忆，“开始专注”展开专注计时。后台任务继续由 `agentos-taskd` 持有，关闭浏览器或图形 Shell 不会取消已接收任务。

## 启动

先启动后台服务；离线规则规划器无需模型凭证：

```sh
cargo run -p agentos-taskd -- --planner rule --state-dir /tmp/agentos-demo
```

另一终端启动图形 Shell：

```sh
cargo run -p agentos-web-shell -- --state-dir /tmp/agentos-demo
```

在浏览器打开 Shell 终端输出的**完整链接**。默认端口是 `4317`，可用 `--port` 更改；也可用 `--socket` 指定已有 daemon 的 socket，不能与 `--state-dir` 同时指定。

链接形如 `http://127.0.0.1:4317/#session=…`，片段中的随机凭证只用于本次 Shell 启动。不要分享该链接。单独访问不带凭证的首页不代表取得后台访问权；重新启动 Shell 后，应使用新输出的完整链接。

未连接后台时，可以体验本地界面、专注计时和浏览器笔记。本地笔记与 daemon 的持久笔记属于两个独立空间，**不会自动同步或补发**。恢复连接后，以服务端任务和笔记事实为准。

### 模型布局配置

Shell 从当前进程环境读取已配置的 `OPENAI_API_KEY`，在服务端调用 OpenAI Responses API；密钥不会传到浏览器，也不需要写入仓库。布局模型与 daemon 的任务规划器独立：即使 daemon 使用离线规则规划器，Shell 仍可调用模型组织界面。

模型名称优先取 `AGENTOS_UI_MODEL`，其次取 `OPENAI_MODEL`，均未指定时使用 `gpt-5.6-terra`。`OPENAI_BASE_URL` 可配置模型服务地址；未设置时使用 OpenAI 的 `/v1` 地址。设 `AGENTOS_UI_MODEL=off` 可在服务端禁用布局模型；界面偏好中的“AI 情景布局”可以在当前浏览器随时开关。

没有模型凭证、模型服务不可用或输出校验失败时，界面继续使用本地语义布局，并明确显示回退状态。模型开关只改变展示，不会切换 daemon 的任务规划器。

## 实时语音与辅助输入

点击麦克风或按 `Alt+V` 后，先阅读说明并主动开启麦克风。界面通过[WebRTC 实时语音接口](https://developers.openai.com/api/docs/guides/voice-webrtc?api=realtime)与模型连续交流，模型直接接收声音并生成语音回应，不再要求每次检查转录后手动提交。需要支持 WebRTC 的浏览器、HTTPS 或 localhost、麦克风权限与可用的实时模型服务；键盘入口始终独立可用。

服务端使用 `OPENAI_API_KEY` 交换浏览器的 SDP，不把项目密钥或可重复使用的模型凭证交给浏览器。`AGENTOS_VOICE_MODEL` 指定实时语音模型，未设置时使用 `gpt-realtime-2.1`，设为 `off` 可禁用；`AGENTOS_VOICE_VOICE` 选择声音，默认 `marin`。模型服务地址沿用 `OPENAI_BASE_URL`。这些配置与 AI 情景布局的模型选择独立，均从 Shell 当前进程环境读取，不需要把密钥写入仓库。

会话启用[语义停顿检测](https://developers.openai.com/api/docs/guides/realtime-vad)：说完后自动回应，开口时可以打断 AI。界面也提供“打断”按钮和 `Esc`，它们停止当前回应并保留连接。麦克风静音只停止输入，不结束会话，也不停止 AI 的声音；结束按钮、`Shift+Esc` 或再次按 `Alt+V` 才会结束对话并释放麦克风。隐藏或离开页面也会结束连接，之后必须主动重连；单次客户端会话最多约 55 分钟。

字幕是展示数据，不会再次触发系统操作。实时模型只有三个应用工具：

| 工具 | 作用 |
| --- | --- |
| `agentos_intent` | 把明确的任务或查询交给现有意图入口与运行时 |
| `show_space` | 切换此刻、专注、记忆、轨迹、时间或能力空间 |
| `focus_timer` | 开始、暂停或重置浏览器计时，支持 25、45、60 分钟 |

只有完整且通过校验的工具调用会执行，同一会话的调用 ID 去重，操作按顺序处理。聊天和字幕不会创建第二份任务。语音没有批准工具，“好的”、声纹或模型文字都不能替代具体步骤的批准控件。打断或结束声音不会取消已接收的后台任务；已经发出的操作即使连接异常，也不能自动重发。

`GET /api/voice/status` 检查实时模型配置，`POST /api/voice/session` 建立连接，`POST /api/voice/hangup` 尝试结束当前网关创建的模型通话；它们沿用本地会话、Host 与来源校验。音频走协商后的媒体轨道，数据通道承载字幕、打断与工具事件。Shell 不持久保存原始音频或字幕；字幕仅在当前页面的内存中保留，开启语音后的音频会传给配置的实时服务，默认是 OpenAI。

已完成的用户话语可以成为 AI 布局的当前意图，任务与笔记摘要也会供实时会话理解上下文。输入草稿、原始音频和批准令牌不参与布局生成。没有后台自动监听、唤醒词或声纹身份验证。偏好中的“键盘操作朗读”使用浏览器 TTS，只作用于实时会话之外，避免两种声音同时播放。

| 快捷键 | 操作 |
| --- | --- |
| `/` | 聚焦意图输入框 |
| `Alt+V` | 连接或结束实时对话 |
| `Esc` | 打断当前回应，或关闭打开的对话框 |
| `Shift+Esc` | 结束实时对话 |
| `Alt+1`–`Alt+4` | 切换此刻、专注、记忆、轨迹 |
| `Enter` | 提交键盘输入的意图；语音无需手动提交 |

动效可以关闭，界面提供文字状态、键盘焦点与读屏提示。专注计时和界面偏好属于浏览器端状态，不是后台能力。

## 模型生成情景的实现

```text
麦克风 ⇄ WebRTC 实时语音模型 ⇄ 语音回应 / 字幕
                    ↓ 完整工具调用
键盘 → 受限工具 / 意图入口 → HTTP / Unix socket → agentos-taskd
                    ↓                              ↓
              布局上下文 ← 任务、步骤和结果事实
                    ↓
          服务端 Responses API + 严格 JSON Schema
                    ↓
              场景校验与真实数据绑定
                    ↓
               受限组件画布
```

`GET /api/layout/status` 返回布局模型是否可用；`POST /api/layout` 接收当前情景，读取 daemon 中的权威任务数据并请求模型。两个接口沿用本地 HTTP 桥的会话凭证和来源校验。Responses API 使用 `store: false` 与[严格结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)，模型只返回场景描述，不调用执行能力。

布局上下文包含已提交的当前意图、选中任务与近期任务的状态及受限参数/结果摘要、笔记预览、专注目标、屏幕尺寸和当前时间。在线任务事实由服务端重新读取；离线时使用明确的浏览器本地内容。输入草稿、原始麦克风音频、批准令牌、会话凭证和模型密钥不参与布局生成。启用此功能会把这些展示上下文发送给配置的模型服务。

模型选择场景标题、说明、面板内容与优先级、面板宽度 `span`，以及下列布局：

| 布局 | 展示方式 |
| --- | --- |
| `ambient` | 空闲与概览，留出环境感与发现空间 |
| `split` | 主要内容与辅助信息并列 |
| `focused` | 聚焦当前一件事，减少同时出现的内容 |
| `stack` | 纵向阅读任务、记录与结果 |

面板限于欢迎、模型提示、建议、笔记、任务、活动、时间、专注和已授权能力。模型提出的顺序和宽度会实际影响画布；窄屏下按阅读顺序收为单列。笔记、任务状态、计时与批准控件仍绑定后台或浏览器的真实事实，不能由模型编造数据或授予执行权限；待批准任务的具体控件不能被模型隐藏。

`crates/web-shell/assets/scene.js` 校验模型方案并绑定事实，保留本地组合器作为回退。模型不能提供可执行字段；未知组件、重复面板或无效优先级会被拒绝。字符串按文本渲染，不执行模型生成的 HTML、脚本或 CSS。

`layout-client.js` 对情景变化防抖 650 毫秒，以相同的上下文指纹去重，并缓存最多 8 个成功方案，缓存期为两分钟。新情景会取消旧请求，旧响应即使迟到也不能覆盖当前画布。失败后不会反复请求同一上下文；上下文改变或点击“重新组织”后才再次生成。输入、批准等交互期间会延后画布替换，避免丢失焦点与草稿。

场景结构有效不等于模型文字准确。模型生成的解释属于辅助提示，任务是否执行与执行结果仍以实际任务详情为准。

场景协议与协调器测试无需模型凭证：

```sh
node --test crates/web-shell/assets/*.test.mjs
```

## 后台、安全与当前能力

Rust 桥只监听 `127.0.0.1`，校验本机 Host、Origin 与每次启动生成的访问凭证，并限制请求体和连接资源。它复用现有 IPC 客户端；规划、持久化、权限和批准仍由 daemon 负责。浏览器不会取得模型 API key。

任务页面展示后台实际状态和结果。提交成功只表示已接收，批准成功只表示已入队；连接中断后不会自动重发变更请求，因为先前操作可能已经生效。

待批准操作必须先读取并展示最新任务、确切能力和完整参数，再由用户明确操作对应的批准控件。批准使用后台当前任务的步骤和原始确认令牌，过期或状态变化后须重新读取。不能用语音“好的”、场景 JSON 或模型建议代替批准；没有可信身份核验设备的 L3 操作仍由后台拒绝。

现有后台内置能力为时钟与笔记的追加、读取、可恢复清空和恢复。文件管理、日历、消息、音乐、窗口管理以及系统级麦克风路由尚未接入。实时语音会把音频传给模型服务，这不同于核心 `Private` 设备“不离开本机”的目标约束；此原型不是全本地语音系统。
