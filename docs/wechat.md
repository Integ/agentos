# 微信

在微信里和 AgentOS 说话：你发的文字交给管家，结果发回微信。

它用的是微信官方给 Agent 开放的通道：微信的 ClawBot 插件和它的 iLink 协议（2026 年 3 月起全量开放）。你在自己的微信里绑定一个机器人，它以聊天对象的形式出现在会话列表里。桥接程序用长轮询收消息，不需要公网地址。

## 使用

1. 把微信更新到最新版本，在「我 → 设置 → 插件」里确认有 ClawBot。
2. 在运行任务服务的机器上登录（会在终端里显示二维码，用微信扫码并在手机上确认）：

   ```sh
   agentos wechat login
   ```

3. 开始收发消息（保持运行；Ctrl+C 停止）：

   ```sh
   agentos wechat
   ```

和工作台一样，`--state-dir` 或 `--socket` 指定连接哪个任务服务。登录信息存在状态目录的 `wechat.json` 里，只有本人可读写。

## 怎么对话

- 直接发文字，就是交给 AgentOS 的一句话，默认接着上一句说；发 `/new` 开始新的对话，`/help` 查看帮助。
- 任务做完，结果发回来；没能处理、失败、被取消，都会如实说，不会说成完成了。
- Agent 用 `ask.user` 提问时，问题发到微信里，你直接回复就是回答。
- 太长的回复会分成几条发。目前只处理文字消息。

## 安全

- **微信里不能批准。** 需要批准的步骤会发一条消息说明是什么操作，请到电脑上批准（桌面的确认面板，或 `agentos approve`），批准后结果再发回微信。批准绑定具体的任务、步骤和令牌，一条聊天消息带不了这些。
- **只听一个人的。** 登录时微信告诉了是谁，就只接受这个微信号的消息；没告诉的话，登录后第一个发消息的微信号被绑定。其他人的消息一律忽略，不会变成任务。重新 `agentos wechat login` 会重新绑定。
- 你在微信里说的话和在终端里打的字一样，以你的身份提交，经过同样的规划和策略：L0 和普通的 L1 直接执行，L2、L3 和读过外部内容之后的副作用都要批准。
- 消息经过腾讯的服务器。不想让某些内容经过微信，就别在微信里说。

## 限制

- 只支持文字，不收发图片、文件、语音。
- 桥接程序重启后会接着上次读到的位置收消息，但正在跟进的任务不会再跟进；用 `agentos task task-N` 查看。
- 登录失效（微信返回错误 -14）时程序退出，需要重新 `agentos wechat login`。
- 镜像没有把它装成开机自动运行的服务（镜像已冻结）。要常驻运行，可以自己写一个 systemd 用户服务运行 `agentos wechat`。
