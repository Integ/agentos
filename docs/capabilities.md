# 网页、文件与定时任务

任务服务自带的三类能力。和其他能力一样，每次调用都经过策略引擎和审计日志，风险等级如实声明。

| 能力 | 风险 | 结果可信吗 | 作用 |
| --- | --- | --- | --- |
| `web.fetch` | L0 | 不可信 | 读取一个公开网页的文字 |
| `files.list` | L0 | 可信（只有名字和大小） | 列出文件工作区里的一个目录 |
| `files.read` | L0 | 不可信 | 读取工作区里的文本文件 |
| `files.write` | L1 | — | 在工作区里写文本文件；替换前自动备份 |
| `schedule.create` | L1 | — | 安排一个定时任务 |
| `schedule.list` | L0 | 可信 | 列出定时任务 |
| `schedule.cancel` | L1 | — | 取消一个定时任务 |

“不可信”的意思是：任务读到这样的结果后就带上污点，之后有副作用的步骤（L1 及以上）都要你确认。网页和文件里的文字可能是别人写的，里面的“指示”不能悄悄动手。

## 网页

`web.fetch` 只读 `http://` 和 `https://` 的公开网页，返回标题和正文文字（去掉脚本、样式和标签），默认最多 2 万字。

- **不能访问本机和局域网。** 网址由规划器决定，而规划器可能在复述某个网页让它说的话；本机上的 Web Shell、Home Assistant，局域网里的路由器，以及云主机的元数据服务都不能这样被读到。检查的是域名实际解析出的地址；连接时钉在检查过的地址上，不会再解析一次，所以无法在检查和连接之间换成本机地址。每次跳转都重新检查，最多跳 5 次。
- **不走代理。** 代理会自己解析域名，绕过上面的检查。
- 只读文字内容（`text/*`、JSON、XML），正文最多下载 2 MB，20 秒超时。按 UTF-8 解码，其他编码的网页可能出现乱码。

## 文件

文件能力只能碰一个目录：文件工作区。默认是 `~/AgentOS`，用 `AGENTOS_FILES_DIR` 换成别的绝对路径；不存在时自动创建（只有本人可访问）。

- **出不去。** 路径都是相对于工作区的；带 `..`、以 `/` 开头的路径被拒绝；符号链接解析之后仍须在工作区里，指向外面的链接读不了也写不了。工作区不能和 AgentOS 的状态目录重叠，否则 Agent 可以借它改自己的策略文件；重叠时任务服务不注册 `files.*`，启动信息里写明原因。
- **写入可以撤销。** 文件已存在时，`files.write` 必须带 `overwrite: true` 才替换，替换前把旧内容复制到状态目录的 `files-trash/<时间>/` 下（结果里写明位置）。没有删除能力。
- 只处理 UTF-8 文本，单个文件最多 1 MB；`files.list` 一次最多列 500 项。

## 定时任务

对管家说“每天早上 8 点告诉我今天的天气”，它会调用 `schedule.create`：

```json
{"text": "告诉我今天的天气", "at": "08:00", "repeat": "daily"}
```

- `at` 是本地时间，`HH:MM` 或 `YYYY-MM-DD HH:MM`；`repeat` 是 `once`（默认）、`daily` 或 `weekly`。只写时间的一次性任务，如果今天已经过了这个点，就是明天。
- 到时间后，任务服务把 `text` 当作一句话提交，任务的来源是 `schedule:<id>`（例如 `schedule:sched-3`）。它和你说的话一样经过规划和策略：有副作用的步骤停下来等批准，批准和回答提问都由这台机器前的你来做，外部调用方和其他定时任务都不能代劳。
- **创建是 L1。** 它会让以后的某个时刻发生事情，所以算有影响的操作，可以用 `schedule.cancel` 撤销。从读过外部内容的任务里创建要你确认，网页里的文字不能偷偷给你安排以后的工作。
- **污点跟着走。** 读过外部内容的任务创建的定时任务会记下这一点，它每次运行都从一开始就带污点，有副作用的步骤都要你确认：被注入的文字就算混过了一次确认，也不能以后每天悄悄动手。
- **最多运行一次。** 到期的定时任务先在磁盘上改成下一次的时间（一次性的直接删除），再创建任务：在这中间崩溃，最多少跑一次，不会重复跑。
- **错过就不补。** 服务每 20 秒看一次；关机等原因错过超过一天的，不再补跑，`schedule.list` 里写明错过了哪一次；错过不到一天的补跑一次。
- 最多 50 个定时任务，每个最多 1000 字。存在状态目录的 `schedules.json` 里。
